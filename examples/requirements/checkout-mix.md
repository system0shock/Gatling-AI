# Требования: нагрузочный тест оформления заказа

## Контекст

Интернет-магазин. Перед распродажей нужно проверить оформление заказа под
ступенчато растущей нагрузкой при постоянном фоновом поиске по каталогу.

## Основной сценарий (оформление заказа)

1. Пользователь открывает список товаров: `GET /products`, ответ 200, JSON со
   списком `items`; для дальнейших шагов нужен `id` первого товара.
2. Пользователь смотрит цену через GraphQL API: `POST /graphql`, запрос
   `price(id)`; ответ 200.
3. Пользователь оформляет заказ: `POST /checkout` с JSON-телом
   `{"productId": "<id>"}`; ответ 200.

Между открытием каталога и запросом цены пользователь "думает" около 1 секунды.

Нагрузка: ступенчатый рост до 10 одновременных пользователей в 2 ступени,
каждая ступень держится 30 секунд.

## Фоновая нагрузка (поиск)

Параллельно основному сценарию каталожный поиск: `GET /search?q=<термин>`,
ответ 200. Термины поиска — из тестового набора (laptop, phone). Интенсивность:
2 запроса в секунду в течение 60 секунд.

## SLA

- p95 времени ответа — меньше 800 мс.
- Доля успешных запросов — выше 99%.

## Окружение

Базовый адрес стенда передаётся через переменную окружения `BASE_URL`.
Секретов и продакшен-адресов в тесте быть не должно.
