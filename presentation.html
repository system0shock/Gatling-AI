Зачем вообще ИИ

Боли инженера НТ

  • Высокий порог входа: Groovy/JSR223, Scala/Java для Gatling, нюансы инструментов.
  • Много рутины: именование элементов, обвязка транзакций, разбор чужих скриптов.
  • Легаси без документации: что вообще тестирует этот .jmx?
  • Долгий путь «требование → запускаемый тест» — дни вместо часов.
  • Миграция между инструментами (JMeter → Gatling) — дорогая и ручная.
Для бизнеса это = время, стоимость, риск ошибок и зависимость от «носителей знания».
Наш подход

Не один инструмент, а набор решений

  • Команды на разной стадии: кто-то живёт в JMeter, кто-то переходит на Gatling-as-code.
  • Один универсальный инструмент не закроет оба мира.
  • Принцип: ИИ-помощник под каждый сценарий, на едином движке Gigacode CLI, встроенный в рабочий процесс.

I

GigaMeter

CLI-first ИИ-ассистент внутри Apache JMeter — агент правит тест-план напрямую.

GigaMeter · CLI-first

Движок — Gigacode CLI по умолчанию

  • CLI-first: бэкенд по умолчанию — локальный CLI-агент GigaCode CLI (или Qwen Code), без API-ключей.
  • Облачные провайдеры скрыты за флагом gigameter.providers.cloud.enabled — архитектура провайдер-агностичная.
  • Тот же корпоративный движок, что и в Gatling-AI Workflow — единая экосистема.

🤖GigaCode CLI

Единый движок Сбера прямо в JMeter. Прайвеси: локальный агент, без облачных ключей.

🔌Транспорт

Windows-safe запуск (cmd /c), таймаут, раздельный дренаж stdout/stderr, явная кодировка.

⏯UX

Стриминг (stream-json), кнопка Stop, сессии --resume, выбор модели в UI.

Совместимость: JMeter 5.5 / 5.6.2, Java 17. Облачные API (при включении флага) остаются как опция.

GigaMeter · команды

Команды как редактируемые Skills

  • Промпты команд вынесены в редактируемые файлы-скиллы: ~/.gigameter/skills/*.md (plan, lint, optimize).
  • Команда подстраивается под стандарты команды — правится без пересборки плагина.

⌨@plan

Генерация / анализ тест-плана: preview → apply в дерево. @plan analyze — разбор готового плана.

🏷@lint

Единый стандарт имён (TG_, HTTP_NN_, JSR_, TC_, EXT_…). Поддержка своего стиля.

⚡@optimize

Рекомендации по оптимизации выбранного элемента.

Базовый набор curated: @plan · @lint · @optimize · @rollback. Регекс-перехват «add a…» для CLI отключён — правки ведёт агент.

GigaMeter · честно

Ценность и ограничения (beta)

Ценность

  • Локальный движок — данные не уходят в облако.
  • Агент правит план: preview → confirm → undo.
  • Снижает порог входа и рутину.

Ограничения сегодня

  • Версия 0.5.0-beta, нужен установленный CLI-агент.
  • Качество правок зависит от схемной валидности ответов агента.
  • Большие планы сериализуются с лимитом; тёмные темы — отдельные фиксы.
Самое рискованное допущение (по дизайн-спеку): стабильность схемно-валидного fenced-JSON от модели. Митигация — валидация ops + preview + откат; запасной путь — встроенный MCP-сервер.

Gatling-AI · границы

Что в scope сегодня

В scope

  • HTTP — end-to-end (генерация, компиляция, smoke).
  • Миграция JMeter (HTTP) + паспорт легаси.
  • Контур качества и отчёты.

Вне scope / позже

III

Вместе

Два инструмента на одном движке Gigacode — единая стратегия внедрения ИИ.

Синергия

Инструменты дополняют друг друга

  • GigaMeter = «улучшить здесь и сейчас»: команда остаётся в JMeter, агент правит план.
  • Gatling-AI = «перейти к коду»: миграция легаси и тесты-как-код с контролем качества.
  • Общий движок: Gigacode CLI работает и внутри JMeter, и как агент Gatling-AI — один вендор, одна экосистема.
  • Переход: навели порядок в JMeter (@lint, @plan analyze) → мигрировали в Gatling агентом → паспорт + quality gate.
